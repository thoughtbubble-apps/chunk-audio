Existing build/browser/Lighthouse checks and ci-required names remain. Tests run with `bun test tests/workflow-safety.test.mjs`.

`deploy` now fails explicitly after source validation: no trusted delivery identity/execution route has been accepted. It checks out no app code, consumes no environment/provider secrets and invokes no provider. This is an incomplete deployment gate, not successful automatic delivery. ci-required still requires deployment success and therefore remains red until that handoff is implemented.

Re-enablement requires reviewed source plus actual accepted CI, not a new label or a boolean repository variable. Current PUBLIC_CI_RUNNER_LABEL and infrastructure/group settings remain unchanged. No credentials should be created, copied, uploaded or printed as part of this change; existing grants have not been assessed or repurposed. No private cache or service-account/Docker access is authorized.

Existing manual owner-operated preview evidence remains separate from automatic delivery. Preserve prior resources/versions for rollback; this workflow does not clean up providers or revoke identities.
